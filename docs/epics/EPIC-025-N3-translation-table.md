# EPIC-025 N3 — Prototype-class → Tailwind/`@/components/wm` translation table

Source of truth for prototype classes: `docs/prototype/assets/app.css`. Usage
examples: `docs/prototype/pages/*.html`. Every N3 page-port wave (B through H)
cites this table instead of re-deriving the mapping. When a class has no
existing `@/components/wm` primitive, the entry says "inline Tailwind" — do
**not** add a new primitive to `components/wm/*` from inside a page PR (that
is a separate, explicitly-reviewed foundation change per the epic's
Acceptance Criteria #2).

## Page shell

| Prototype class                                               | Real app equivalent                                                                                                                                                                                                                                            | Notes                                                                                                                                                         |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Rule for anything not in this table

If a wave needs a prototype class not listed here: (1) check `app.css` for its
definition, (2) check whether an equivalent already exists in
`@/components/wm` or `@/components/ui`, (3) if not, inline the Tailwind
translation in the page file — never add to `globals.css`, and only promote
a page-local pattern to `@/components/wm` via a separate, explicitly-reviewed
foundation PR (per the epic's Acceptance Criteria #2). Append genuinely new,
reusable entries discovered by a later wave to this table instead of
duplicating the derivation in that wave's own docs.
