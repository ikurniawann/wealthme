# UI/UX consistency spec — audit of 2026-10-11

status: on-progress
environment: dev
owner: Opus (execution) · author: audit session 2026-10-11

## Why this exists

A full end-to-end crawl of https://wealthme.demo-wit.id (demo user, EUR display currency,
560 seeded transactions) at desktop 1440×900, tablet 834×1112 and mobile 390×844 opened every
page, every tab/select option, every dialog, menu and sheet the crawler could reach, typed sample
data into every form (empty submit → filled → submitted on desktop) and screenshotted each state:
~1 500 screenshots. Eight reviewers then scored every route for **Karakter / Konsistensi /
Kerapian** (1–5) and logged defects (P0 broken or data contradiction · P1 clearly sloppy · P2
polish · P3 nit).

Verdict: the forest/lime bento foundation has character (Karakter mostly 3–4), but
**consistency and tidiness are 2/5 almost everywhere**. The product is not yet "rapi": 58 P0 and
202 P1 defects on desktop alone. Most of them are not per-page bugs but eight systemic failures
repeated on every page. Fix the systems first (workstreams W1–W9), then sweep the per-route lists.

## Non-goals

- No visual redesign. The design system (forest/lime bento, `bento.css`, `.wm-*`, `.dialog`) stays;
  this is about applying it consistently and making numbers honest.
- No production deploy. Verify on dev only.
- Seed data cosmetics ("Bulk pagination test NNN") are P3; do not spend time on them before W1–W9.

## Workstreams (systemic, do these first)

Each workstream lists the acceptance criteria that close it. "Every page" means all 27 routes
under `apps/web/src/app/(app)/`. Reuse `@/lib/format` / `useMoney` / `useMoneyFormatters`; do not
add page-local formatters.

### W1 — One currency everywhere (P0)

The account's display currency (EUR for demo) must be the only currency the user sees unless an
IDR figure is explicitly labelled as the statutory/stored value.

- [ ] No hardcoded "Rp", "jt", "M", "B" anywhere a formatted amount is shown. Known sites:
      beranda Tujuan rows ("42 / 60 jt"), beranda hero line-chart axis ("30M / -10M"), ringkasan hero
      axis ("1.5B"), transaksi hero headline ("-Rp 3.187,35"), Tambah Transaksi account chips
      ("Rp 128.450.000"), notifikasi bodies ("Rp 60.000.000"), akun Keamanan (">Rp 5 jt"), rekening
      tax note ("≤ Rp 7.500.000" → add the € equivalent), asuransi hero ("Rp ≈ € 74,86"), mastercoa
      guide dialog, mobile hero "Rp" chip (beranda, Pengeluaran card), splitbill shares
      ("EUR 416666,67" → "≈ € 416.666,67").
- [ ] Every chart axis uses the display-currency tick formatter (compact: "€ 1,5 rb", "€ 2 jt"
      follow the existing compact rules in `@/lib/format`). Known sites: beranda line chart, ringkasan
      hero, anggaran bars ("0 / 5 jt / 10 jt" for €40–150 budgets), laporan Tahunan (50M–200M), dana
      trend (5M/15M), kalkulator Investasi (200M–600M), liabilitas projection (600M/400M/200M, no unit).
- [ ] Every form label that says "(Rp)" on a € input is replaced with a currency-neutral label and
      the currency comes from the selector: anggaran, investasi, aset, liabilitas, asuransi, kalkulator
      (all inputs), donation zakat, tujuan. Placeholders use €-scale examples, not "200.000.000".
- [ ] The "IDR" tab on ringkasan is labelled with the actual display currency; switching Valas
      converts every card or the control is visibly scoped to the hero.
- [ ] Sign/≈ order is one format everywhere: `≈ -€ 530,50` (never `-≈ € 45,22`).

### W2 — One form system (P0)

- [ ] Every create/edit form validates on the client, in Indonesian, inline under the field with
      an error border, and focuses the first invalid field. No browser-native "Please fill out this
      field." tooltips (investasi, aset, mastercoa, rekonsiliasi templates), no toast-only validation
      (anggaran, asuransi, splitbill, warisan, donation), no silent no-op submit (Tambah Transaksi on
      beranda/transaksi/rekening/quickinput: Akun and Kategori unselected → nothing happens).
- [ ] Required fields carry the asterisk marker consistently (Tambah Transaksi has them; Tambah
      Rekening, Tambah Aset do not).
- [ ] Ranges are enforced client- and server-side: percent fields 0–100 (aset "Perubahan Nilai",
      liabilitas "Bunga Anuitas" currently 500s at 1250000, tax "Tarif sendiri" surfaces
      `rateBpsOverride must not be greater than 10000`), auto-debit day 1–28 (tujuan), target dates in
      the future (tujuan accepts yesterday), dates formatted before submit (tax surfaces
      `occurredAt must match /^\d{4}-\d{2}-\d{2}$/`).
- [ ] Server errors are mapped to a field and translated; never show a raw backend string
      ("Internal server error", "A budget already exists for this category", "COA code … must be
      exactly 5 digits", "username may only contain…"). Add a shared `apiErrorToFieldError` helper.
- [ ] Success = dialog closes, one success toast, the list/KPIs refresh with the new record. Toasts
      never stack on a stale toast and never cover the dialog footer or the new record (place
      bottom-right with offset; dismiss previous on new submit).
- [ ] Dialogs reset their state on open (anggaran "Kategori baru" currently reopens with the last
      values); a dialog opened from a filtered page preselects the active filter (transaksi → Akun).
- [ ] Amount inputs: full-width, thousand separators while typing, never truncated ("1.250.0",
      "250.00", "1.250" seen in anggaran, asuransi, liabilitas); currency + period selectors on their
      own row. The three-line FX helper ("1 EUR = Rp … · Nilai rupiah final … · Disimpan sebagai IDR")
      appears once per form, collapsed to one line with an info tooltip — not under every money field.
- [ ] File inputs use the styled upload control, never the raw browser "Choose File" (aset edit).
- [ ] No native `<select>` or native number spinner inside the dark hero or cards (ringkasan
      period select; percent inputs).

### W3 — Honest states: loading, empty, error (P0)

- [ ] A failed or throttled API call renders an error state with retry, never the empty-state copy.
      Today "Belum ada transaksi" / an empty hero chart appear on 429/500 (beranda, transaksi). Add a
      shared `QueryState` wrapper (loading skeleton / error / empty / data) and use it in every card.
- [ ] Loading never looks like empty: skeletons for lists and charts; empty copy only after a
      successful empty response.
- [ ] Charts have an explicit empty state ("Belum ada data untuk periode ini") instead of a 380px
      dark plot with one axis (transaksi filtered, investasi tabs).
- [ ] Every action gives feedback: "Cetak PDF" (laporan) currently does nothing visible;
      "Perbarui harga" (investasi) shows a success icon while in progress and never completes;
      "Ekspor CSV" is enabled on 0 rows; KPI tiles that look clickable but do nothing (investasi
      Untung/Modal) lose the affordance.

### W4 — Numbers agree with each other (P0)

Each item is a data/aggregation bug; fix in the hook or API, not with copy.

- [ ] laporan: one data source and one period definition for all 17 reports. Today Ringkasan/Grup
      Keluarga/Arus Kas say income €10.012,27 / spend €13.299,44 while Bank/Detail/PNL say
      €9.874,95 / €12.242,49; Detail's KPI strip (−€14.398,51) ≠ its hero (€12.242,49); "Gaji" is
      €10.095,64 / €8.143,28 / €8.280,59 across tabs; Tahunan 2026 income < 6-month income; Aliran
      Dana sources sum to more than total income; the Arus Kas Sankey middle node labels the expense
      total as "Pemasukan".
- [ ] anggaran: hero "0% dari batas" while categories are 266–1194% over; weekly budgets are folded
      into the monthly total (normalise per period); the over-budget alert names the wrong category;
      paying a Kewajiban must register as terpakai and must not create a 0% budget; paid items leave
      "Kewajiban Belum Dibayar"; bars must draw terpakai over a batas outline so over-budget reads as
      over-budget. Beranda's budget card and anggaran must come from the same computation.
- [ ] tujuan: goals with no routine allocation count as "Perlu didorong" (today every goal is
      "Sesuai rencana" while detail sheets warn in red); 100% goals do not offer "Setor" as primary.
- [ ] warisan: allocation percentages round once so hero legend (63% + 38%), side stat and
      "37% belum dialokasikan" agree; the hero does not repeat the same total twice.
- [ ] asuransi: inactive policies are excluded from "Uang Pertanggungan per Jenis" (or the header
      total includes them); the 30-day renewal reminder counts a policy at "0 hari".
- [ ] donation: "Daily average" is total ÷ count and lags the count after a second add — define one
      metric, name it in Indonesian ("Rata-rata per donasi"), compute from the same list; the chart
      keeps every category after an outlier add.
- [ ] "Daily average" everywhere else (rekening = total ÷ accounts, quickinput "4 transaksi" vs
      "73 minggu ini", iam "12 halaman", mastercoa "18"): either a real daily average over a named
      window, or remove the stat from heroes where it is meaningless (iam, mastercoa).
- [ ] masterdata "106 akun · Kategori yang sudah punya akun COA" vs mastercoa "89 belum terhubung /
      21 terhubung": subtitle must state linked vs total.
- [ ] akses-saya: rows derive from the current role (Master shows "Mengubah role anggota —
      Dikunci", badge "Read + Input terbatas", "Saldo keluarga: Tidak terlihat" while IAM says "Akses
      penuh").
- [ ] notifikasi: items are categorised by type (insurance renewal → Jatuh Tempo, savings target →
      Tujuan), hero legend counts follow.
- [ ] rekonsiliasi: Cocok / Perlu ditinjau / Belum cocok show real counts (or 0) for the latest
      document; step 1 "Upload" is "Menunggu" until a file is chosen; the AI scan step has progress,
      cancel and an error path, and is gated on the family AI key with a clear message when absent.
- [ ] transaksi: the type tabs (Masuk/Transfer/Kartu Kredit) filter every hero figure, not only
      "Jumlah transaksi"; "100% terkategori" hides when count is 0; future-dated rows are flagged
      "Terjadwal" or excluded, and beranda Riwayat / transaksi Terbaru agree on the newest row.
- [ ] ringkasan: hero chart re-queries per unit and period (today it is one flat line on a 1.5B
      axis for every selection); hero "-35%" and the Skor kesehatan gauge "0%" read one ratio; the
      "Perlu Perhatian" badge matches its message; Komposisi vs Rincian use one taxonomy.
- [ ] beranda: 7h/30h toggles filter the Riwayat list (today both show the same rows); hero
      "Kesehatan finansial" and hero "Selisih" state their windows in the label.
- [ ] investasi: "Perubahan Hari Ini —" vs "Terakhir sinkron 11 Okt" (today) — compute or explain.
- [ ] laporan Harian: "dari 2 transaksi" counts a transfer; count or exclude consistently.

### W5 — Charts (P1)

Introduce one chart wrapper (in `@/components/charts`, foundation change allowed by this spec)
that every page uses, with:

- [ ] axis gutters so no tick label is ever clipped (".359,56", "€ 2.718,90", "€ 49.907,82",
      "€ 24.641,99" are clipped on beranda, ringkasan, laporan, transaksi, tujuan, investasi, rekening,
      liabilitas, kalkulator) and 3–4 gridlines, not only max and 0;
- [ ] exactly one legend per chart (investasi, liabilitas, tujuan, laporan Arus Kas each render two,
      sometimes in opposite order);
- [ ] x-labels that are distinct and not truncated to the first word (tujuan "Dana"/"Dana",
      anggaran "Tagihan"/"Makan", rekening "BCA"/"BCA", investasi "Bank"/"Telkom") — use short names +
      tooltip;
- [ ] outlier handling: one large item must not flatten the rest to 2px (tujuan, investasi,
      donation) — percent-progress bars or capped axis with annotation;
- [ ] fixed plot height independent of neighbouring cards (iam hero chart is cut off until the
      neighbour grows; beranda line chart fills half its hero and drops its legend);
- [ ] a visible empty state; negative values in the danger colour, never lime (laporan "≈ €3.287,17
      pengeluaran melebihi" in green; Selisih dots).
- [ ] The mobile beranda "Statistik 7 hari" dot-matrix reads as a broken placeholder; replace with
      the same diverging bars as desktop at phone scale.

### W6 — One dialog system (P1)

Today the same product uses: centred modal with green gradient header (Tambah Transaksi, Bayar,
delete confirms), white-header right side-sheet (Tambah Rekening, Tambah/Edit Anggaran), green-
header side-sheet (Ubah tampilan kartu), ~680px sheet (Catat Investasi) vs ~460px (others).

- [ ] Decide once in `docs/design/`: side-sheet for create/edit records, centred modal for
      confirmations and short pickers. Apply to every dialog; one header style; close button centred
      in the header band; no hairline between title and subtitle (Bayar, Filter periode, delete
      confirms show a stray 1px rule); no drop shadow on primary buttons.
- [ ] Footer buttons are two tiers only: primary filled, secondary outline; destructive is a ghost
      with confirm (Edit Anggaran's solid red icon-only delete is the widest control; "Simpan
      Perubahan" wraps and clips its arrow).
- [ ] Every dialog opens fully in view (ringkasan Kustom date range opens scrolled off the top;
      transaksi date popover covers the Akun label) and never exceeds the viewport width (warisan heir
      table overflows the sheet).
- [ ] Edit sheets show context, not 550px of white (Edit Anggaran lacks terpakai/%; goal detail
      sheets lack Terkumpul/Target); every dialog has the one-line description under the title.
- [ ] Account-chip carousel in Tambah Transaksi: no clipped 4th chip under the chevron, no
      truncated "BCA Tahapan ···9…", balances in €; Jumlah field has one focus treatment and the
      dialog does not jump 9px between states; currency pill uses an SVG flag (today a tofu box
      "☒☒ EUR"; same in the ringkasan Valas listbox).

- [ ] Floating AI launcher is inset from the viewport edge on every page (it is cut in half and

- [ ] KPI grids never orphan one card on a second row (laporan Harian/Tahunan/Grup Keluarga) — 4-up
      or 2×2.
- [ ] Segmented controls fit on one line (transaksi type tabs wrap "Kartu Kredit"; tax PTKP and

- [ ] Action buttons keep a fixed position across states (transaksi Ekspor/Catat jump rows on empty

- [ ] Filters sit above the content they filter (investasi type filter is a lone pill at the page

- [ ] Tables: numeric headers right-aligned with their values (laporan Bulanan), no clipped last
      column (laporan Detail JUMLAH; mastercoa long names overflow the grid, "Maintenanc e" mid-word

- [ ] Card heights in a row match (laporan "Ke mana uangnya"/"Dibanding bulan lalu" end 60px apart;

- [ ] Hero cards carry no drop shadow (rekening); headline figures sit on one baseline across sibling

- [ ] No English in the Indonesian UI: "On Track", "Daily average", "Budget Type", "Pending",
